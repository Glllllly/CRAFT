# Agentic业务拓展进展

# 目标
探索Agent框架在业务拓展场景的能力边界，并寻找新技术可落地的应用场景。

# 进展与发现

## 实现
主链路：基于Agentic RAG架构和某大语言模型搭建  
工具：9个通用工具接口  
- 内部文档搜索工具：根据查询词检索内部知识库文档  
- 赢单客户信息查询工具：根据查询词获取赢单客户相关数据  
- 客户基础信息查询工具：检索客户基础资料  
- 客户详情获取工具：通过客户标识查询完整客户信息  
- 客户跟进记录查询工具：根据关键词、客户标识等条件获取跟进数据  
- 互联网公开信息搜索工具：通过多关键词检索公开网络信息  
- 全客户信息搜索工具：结合多条件筛选客户数据  
- 赢单客户筛选工具：多条件过滤赢单客户信息  
- 文档格式转换工具：将特定格式内容转换为内部协作文档格式  

## 发现
评测详情：内部Agent助手效果评测  
补充说明：基准为现有业务助手线上效果，对比模型为基准模型  
简单问答场景：已达到或超越现有业务助手水平，核心优势为问题拆解与反思能力  
方案生成、周期业务复盘等场景：可更全面地检索资料、支持定制化输出，部分场景表现优于传统工作流  

## 用户调研
对现有业务助手的重度用户进行调研，收到能力优化期待，计划基于当前框架支持：

| 场景 | 用户反馈 | 计划支持方式 |
| --- | --- | --- |
| 客户调研 | 常规提问内容深度不足，总结缺少关键方向 | 在prompt中增加上下文信息以丰富报告分析维度 |
| 缺少对特定主体信息的深入挖掘 | 通过prompt补充任务初始规划以强化该类信息查询 |  |
| 基础查询与深度调研结果需整合为统一文档 | 调用文档生成工具实现 |  |
| 批量查询多维数据并二次提取字段 | 支持单表查询与循环任务后调用对应能力 |  |
| 调研后匹配相关市场活动 | 基于现有原子能力补充任务规划 |  |
| 按榜单生成客户列表并调研 | 结合公开信息查询、客户调研等能力理论可行 |  |
| 方案生成 | 缺乏自主客户调研能力 | 任务初始规划阶段增加客户调研步骤 |
| 生成内容与客户关联性弱 | 通过prompt优化任务规划以提升灵活性 |  |
| 召回资料固定且时效性不足 | 使用内部文档搜索工具获取最新资料 |  |
| 场景缺乏整体概括 | 在prompt中增加总结约束 |  |


# 存在问题

| 遇到的问题 | 尝试过的解法和效果 | 后续解决问题的思路 |
| --- | --- | --- |
| 缺少上下文理解，如不熟悉用户场景、专有词汇，对复杂任务处理简单 | 1. 在系统prompt中补充角色描述与业务背景知识，简单问题效果显著；2. 增加复杂任务初始规划指令，但执行不完全 | 在系统prompt中要求任务开始前先进行上下文召回 |
| 工具调用混淆，相似功能工具易误用 | 修改工具描述后，文档与客户查询可区分，但赢单客户与普通客户查询仍易混淆 | 1. 在prompt中明确术语定义；2. 合并相似工具为统一接口，通过参数区分功能 |
| 上下文窗口长度限制，影响复杂场景效果 | 通过限制输出长度走通基础场景 | 采用分步生成+文档实时编辑模式优化 |
| 指令遵循度不足，部分步骤未按要求执行 | 调整prompt补充知识未干扰主链路，但效果有限 | 在系统prompt中引入业务任务处理策略 |
| 复杂格式数据处理需额外工程适配 | - | 1. 工程层优化格式转义；2. 兜底采用RPC调用处理参数 |
| 高级任务编排（如循环）支持困难 | - | 采用多Agent架构拆分任务独立执行 |
| 多步任务中间结果需缓存 | - | 设计中间结果缓存机制 |
