# Review

# Review工作内容
对分配的需要Review的业务系统模板，先从整体上判断是否属于该行业、场景的最佳实践，也就是根据自己对行业、场景的理解，判断这个模板是否具有行业&场景的普适性。如果大部分同行业、同场景的都适用，那就可以作为最佳实践留下来。
目前对不同行业、场景的业务系统最佳实践，较难有一个公认的标准。某类角色是内部可用资源中，能拉通不同客户共性需求的合适人选，因此，就以该类角色对业务系统的最佳实践判断作为初始标准。
如果判断不属于最佳实践的，可以看下自己手里有无更好的模板，如有可以补充作为最佳实践进行后续Review。如无，则该模板标记不可用，进入下一个模板的Review。
无论是判断为最佳实践，或者补充类新的模板作为最佳实践，都可以开始接下来的模块Review。Review方式为在确定的最佳实践模板上另存副本，然后在副本上直接修改，原件不动。
先根据业务系统需要，判断对应的数据表、视图是否完备。对缺失的数据表、视图进行补充，冗余的数据表、视图进行删除。
数据表、视图确定下来之后，对每个数据表的字段进行逐个Review，包括字段类型的检查、对缺失字段进行补充、冗余字段进行删除。这里需要注意，部分字段可能在数据表中隐藏，可以取消隐藏后再Review。
当数据表、视图、字段都确定了，就可以Review仪表盘了。对一些必要但缺失的仪表盘进行补充，对不需要或重复的仪表盘进行删除，对于需要但命名表述存在问题的仪表盘进行修订。
对业务系统中的自动化、工作流进行Review，判断这些自动化、工作流是否为最佳实践的业务系统必要。对不需要的进行删除、对缺失的进行补充。补充的时候按照工作流进行补充即可。
较早的模板中自动化较多，工作流是后来新上的功能。所以新增的时候优先以工作流的形式说明，如果搭建工作流比较费时，可以直接在标注文档后面备注需要补充什么工作流也可以。
如果业务系统有高级权限设置，可以检查高级权限中的角色划分是否合理，对不需要的角色进行删除，缺乏的角色进行补充。确定角色后，再检查对应的权限配置是否合理，如果不合理，直接进行修改。
完成以上工作后，对于删除、新增的内容，需要根据可能的全局依赖关系，对相关引用进行通盘Review，以判断是否有删除的内容在其他地方使用到，导致对应的模块不可用。例如：删除了某个字段后，影响了其他公式字段、工作流的触发条件等。
